# Build Engine Notebook

This folder contains a notebook workflow to build TensorRT engines for SqueakView DeepStream inference.

Primary file:
- `build_engine.ipynb`

What it does:
1. Takes a model input (`.pt` or `.onnx`).
2. If input is `.pt`, exports ONNX with Ultralytics `yolo export`.
3. Builds a TensorRT engine with `trtexec`.
4. Emits a DeepStream config snippet that points to the ONNX + engine.

## Why this matters

DeepStream multi-camera inference requires engine batch size to match the number of camera streams.  
If batch size mismatches, you can see no detections, laggy preview, or runtime rebuild attempts.

## Batch Size Rules

- 1 camera setup:
  - Use `IMG_SIZE = (1, 3, 640, 640)` in notebook.
  - DeepStream config `batch-size=1`.
  - Engine should be built as batch 1.

- 2 camera setup:
  - Use `IMG_SIZE = (2, 3, 640, 640)` in notebook.
  - ONNX export must include `batch=2` (already wired in notebook export command).
  - DeepStream config `batch-size=2`.
  - Engine should be built as batch 2.

## Recommended Build Practice

Do not overwrite old engine files when changing batch size.

Use explicit engine names, for example:
- `mousehouse_pose_fp16_b1.engine`
- `mousehouse_pose_fp16_b2.engine`

Then point DeepStream config to the correct one.

## Typical Notebook Flow

1. Edit config cell:
   - `INPUT_MODEL`
   - `IMG_SIZE`
   - `PRECISION`
   - optionally `ENGINE_OUTPUT`
2. Run notebook top-to-bottom (Kernel -> Restart & Run All recommended).
3. Confirm build cell output shows expected input shape:
   - batch 1: `1x3x640x640`
   - batch 2: `2x3x640x640`
4. Update runtime DeepStream config:
   - `onnx-file=...`
   - `model-engine-file=...`
   - `batch-size=<camera_count>`

## Common Pitfalls

1. Notebook state mismatch:
   - source cells edited, but old outputs from previous run still shown.
   - fix: restart kernel and run all.

2. Engine/config mismatch:
   - using batch-1 engine with `batch-size=2`.
   - fix: build and select matching engine.

3. Wrong ONNX path:
   - config points to missing ONNX file.
   - fix: use ONNX path generated by notebook.

## Validation Checklist Before Running GUI

1. DeepStream config `batch-size` equals camera count.
2. `model-engine-file` exists and matches intended batch.
3. ONNX path in config exists (needed for rebuild/fallback).
4. GUI camera count matches inference batch expectation.
